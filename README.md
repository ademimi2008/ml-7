# Практическая работа № 7. Случайный лес: прогноз оттока абонентов

Ноутбук `practical_work_7_random_forest.ipynb` обучает случайный лес на датасете `o_churn_synthetic_1.csv`, сравнивает его с одиночным деревом и анализирует важность признаков.

## Данные

Файл `o_churn_synthetic_1.csv` (синтетические данные оператора связи):

- 3000 абонентов, 13 столбцов, пропусков и дубликатов нет;
- задача: бинарная классификация, целевая переменная `churn` (1 = ушёл, 0 = остался). Ушло 1114 абонентов (37,1 %), осталось 1886 (62,9 %), классы умеренно несбалансированы.

| Столбец | Тип | Описание |
|---|---|---|
| `subscriber_code` | число | идентификатор абонента, **не признак**, из модели исключается |
| `region` | категория (9 значений) | регион |
| `tariff` | категория (4 значения) | тариф: Базовый, Смарт, Безлимит, Семейный |
| `tenure_months` | число | стаж абонента, месяцев |
| `monthly_charge_som` | число | ежемесячный платёж, сом |
| `internet_gb` | число | интернет-трафик, ГБ |
| `support_calls_3m` | число | обращений в поддержку за 3 месяца |
| `autopay` | 0/1 | подключён автоплатёж |
| `days_since_topup` | число | дней с последнего пополнения |
| `topups_3m` | число | пополнений за 3 месяца |
| `dropped_calls_pct` | число | доля оборванных звонков, % |
| `balance_som` | число | баланс, сом |
| `churn` | 0/1 | **целевая переменная** |

Особенности, которые нужно учесть:

- `subscriber_code` это идентификатор. Если оставить его среди признаков, лес может подгонять модель под случайные номера, а в графике важности он появится как «важный» признак. Удалите его до обучения.
- `region` и `tariff` строковые. Случайный лес в scikit-learn не принимает строки, нужно закодировать (`pd.get_dummies` или `OneHotEncoder`). После кодирования признаков станет больше 11, учитывайте это в разделе про удаление признаков.
- В `region` есть значения «Ош» и «Ошская». Возможно, это город и область, но проверьте, не дублируют ли они друг друга, и объясните в работе, как вы с этим поступили.
- Классы несбалансированы (37 / 63), поэтому смотрите не только accuracy, но и F1, precision и recall по классу `churn = 1`. Для разбиения используйте `stratify=y`.
- Данные синтетические. Выводы относятся к этому датасету, а не к реальным абонентам.

## Установка

Нужен Python 3.9 или новее.

```bash
pip install pandas numpy scikit-learn matplotlib jupyter
```

Если работаете в VS Code, выберите ядро из вашего `.venv`. В Google Colab всё нужное уже установлено, достаточно загрузить CSV.

## Запуск

1. Положите ноутбук и `o_churn_synthetic_1.csv` в одну папку (имя файла в `pd.read_csv` должно совпадать с вашим).
2. Откройте ноутбук и выполните все ячейки сверху вниз (Restart and Run All).
3. Впишите свои выводы в ячейки, помеченные «впишите».

Везде зафиксирован `random_state=42` для воспроизводимости.

## Что делает работа

1. Загрузка и осмотр данных, баланс классов.
2. Подготовка: удаление `subscriber_code`, кодирование `region` и `tariff`.
3. Одно разбиение train/test (stratify) для всех моделей. Это нужно, чтобы дерево и лес сравнивались на одних и тех же данных.
4. Одиночное дерево и лес с параметрами по умолчанию: метрики на train и test, разрыв между ними.
5. Число деревьев: кривая OOB-оценки (out-of-bag) в зависимости от `n_estimators`, обоснование выбора.
6. Подбор `n_estimators`, `max_depth`, `min_samples_leaf` через `GridSearchCV` с кросс-валидацией только на train. Дерево настраивается на тех же фолдах.
7. Итоговое сравнение: дерево и лес, каждый по умолчанию и настроенный.
8. График важности признаков (MDI и перестановочная важность на тесте).
9. Эксперимент: удаление наименее важных признаков и проверка, падает ли качество.
10. Вывод: какие признаки можно исключить без потери качества.

## Чего нельзя делать

- Оставлять `subscriber_code` среди признаков.
- Подбирать параметры или отбирать признаки по тестовой выборке.
- Сравнивать дерево и лес на разных разбиениях.
- Оставлять лес по умолчанию без объяснения, почему настройка не потребовалась.
- Ориентироваться только на accuracy при несбалансированных классах.
- Интерпретировать важность признаков как причину оттока: это ассоциация в синтетических данных.
- Сдавать ноутбук с пустыми выводами или ошибками в ячейках.
